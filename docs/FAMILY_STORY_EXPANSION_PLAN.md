# 家族玩法与剧情扩充计划（Grok 4.6 执行入口）

日期：2026-09-09。实现基线：`77a98bb`。

本文记录下一轮开发计划，文档提交不代表功能已实现。请在当前家族玩法和图形 UI 上实施，不重启旧版轮回系统。本文是本轮范围入口；旧计划提供背景，发生范围冲突时以本文及根目录 AGENTS.md 为准。

## 1. 产品目标与约束

- 长期成长主体是家族；每代是一段短篇任务，只有一个明确主目标，约 3–5 分钟完成。
- 家族住房、工具、知识记录、信誉应给下一代提供可见的新解法；个人能力仍需本代学习。
- 职业由家境、随机机会和实际选择共同形成，童年或已有资产不能直接锁死职业。
- 采用现实生活逻辑，不引入穿越、前世记忆或无来源的能力继承。
- 场景、人物动作、物件、图标和数字承担主要表达。保留必要的简短对话；完整说明放可选详情。
- 点选行动即推进，反馈在下一幕出现，不增加确认页。家园间歇最多建设一次，允许直接开始下一代。
- 开发可玩优先，只做相关必要验证，不扩展成完整人生模拟、复杂经济模拟或通用剧情编辑器。

## 2. 当前实现与主要问题

当前循环：家园建设 → 按家族条件分配主线 → 六个固定事件 → 结算资金、资产和经历 → 下一代。

四类积累各两级。现有主线为稳住生活、取得独立做工资格、小铺稳定接单；任务选择存在经营优先于做工、做工优先于生活的固定优先级。满足高阶条件后容易持续重复。

事件随机变体主要替换标题、描述和场景，选项效果与后续路径基本不变。个人动手和交涉有少量用途，筹划缺少有效门槛。跨代记录有资产和经历，缺乏持续关系及其后续事件。内容整体收束到木工经营。

本轮解决三个问题：选择真正改变后续处境；上一代积累产生明显用途；不同代有不同机会及延续的故事。既有结算等细节问题不单独扩大为修复项目，仅处理阻碍本轮基本可玩的部分。

## 3. 本轮必须交付的范围

1. 重做现有经营主线，至少两条实际不同的路线及对应结局。
2. 新增一条与经营结构不同的“雨季安居迁居”主线。
3. 引入两组可持续的关系：邻居一家、镇上商行。每组至少有一次本代形成事实、后代产生后续的闭环。
4. 住房保障、工具资产、教育、信誉各有至少一个明显改变解法的场景。
5. 按条件与机会分配任务，并在存在其他可玩任务时抑制最近任务的连续重复。
6. 图形 UI 能显示分支造成的场景变化、行动机会、成果及关系来源。

先完成上述闭环。其他职业、更多主线与大规模事件池放到后续，不以文案数量作为完成标准。

## 4. 任务结构与有意义的取舍

将严格按数组下标推进的任务扩展成小型分支：遇到问题 → 选择办法 → 新处境 → 运用积累 → 结局。允许分支重新汇合，但需保存并兑现路线选择的后果，不能只更换文字。

优先只增加一种资源约束：有限行动机会，用日历格表达。建议关键阶段三次行动，整代保持约 4–6 次有意义的选择；具体数值以短时试玩调整。学习、采购、制作、帮人会消耗机会；请人可用钱换时间。主界面不新增体力、饥饿、心情等多排数值。

机会耗尽进入相应结算或补救出口，不出现所有按钮都锁住。查看详情、家园操作不消耗机会。成本与预告要使用实际计算结果，不能显示原始文案中的过期数值。

学习必须在本代后续一至两次行动内有实际回报。筹划如保留，应提供明确用途，例如提前安排备料节约机会；暂时没有用途时从主界面弱化，不增加空属性。

## 5. 重做经营主线

唯一目标：形成能够持续接活的生意。

本轮至少完成以下前两条路线，第三条为后续候选：

| 路线 | 选择与困难 | 长期成果 |
| --- | --- | --- |
| 商行订单 | 备料投入、赶工、分批交付；收益集中，期限紧 | 商行往来、后续订单机会 |
| 街坊维修 | 在有限时间内安排维修、兑现承诺；单笔收益较低 | 本地客源、邻里协助 |
| 工匠合做（后续） | 分工、分成、协调 | 合作渠道 |

两条必做路线各有至少一个专属后续情境和一个不同的家族结果；不能使用相同按钮效果，仅更换人物与插图。现金较少的路线也需要可兑现的价值，不让最高收入选项全面占优。

每单完成只兑现一次，分批交付需与实际未完成部分对应。必要时随本轮重构解决重复兑现，避免新分支放大旧问题。

## 6. 新主线：雨季安居迁居

唯一目标：雨季前找到能继续生活、做工的地方。

开场以漏水屋顶、受潮木料、三格时间表达问题。一句短对白交代紧迫性。提供以下解法，并根据已有资产调整成本与机会：

| 解法 | 代价与中段事件 | 结局 |
| --- | --- | --- |
| 修旧屋 | 材料和动手要求；备料或修补取舍 | 保住自有场地，现金较少 |
| 借邻居院子 | 帮忙搬粮或搬家具；安排搬运顺序 | 临时场地、互助关系 |
| 租商行后院 | 租金或约定工作；安排交付与搬入 | 新客源、明确且有限的后续责任 |

既有住房不能在开场无理由被判定全部失效；根据家族状态呈现修缮、保护工作场地或转移材料。已经足以解决问题的资产应兑现优势，或降低此任务出现权重。

关键变化可以是渡口即将关闭，需要先搬工具或先兑现帮忙的约定；提前以水位、停航告示等给出线索，不在结算时突然随机判失败。

家族资产的表现：工具帮助拆装搬运；工艺笔记帮助识别修补办法；生活储备让本代腾出行动；商行信誉带来借车或分期搬入的机会。资产提供便利，不直接继承熟练技能。

部分完成也有后续：保住部分工具、获得临时住处等。每次结算清楚显示留下了什么，避免失败后无事可做。

## 7. 跨代关系与随机机会

用少量明确事实表达关系，不先引入通用好感度系统。事实包含稳定标识、对象、来源代次、发生事件和是否已兑现，例如“沈家帮邻居搬粮”“商行借给沈家一辆车”。

下一代通过这些事实获得一次协助、介绍机会或履行约定；兑现后更新状态，避免无限领取回报。长时间跨度中持续的是家庭和组织，不能让同一位老人跨几代仍以相同年龄出场。

任务候选由家族条件、地方机会和近期历史共同决定。使用存档中的确定性随机状态，恢复游戏不重抽机会。只有一个可用任务时允许重复并保证可玩；有替代任务时降低最近任务权重，去掉高阶任务永久压过其他任务的规则。

随机选择的是完整情境，包括场景、可用行动、代价及后续节点。已选择的路线保存到运行状态，不在每次渲染时重新抽取。不要求实现一个可任意组合所有事件的生成系统。

## 8. 图形表达

- 顶部突出唯一目标、剩余机会和关键进度；其余属性进入可选详情。
- 主场景随行动改变：材料搬入屋内、车装满、屋顶修好、订单装车、招牌挂起。
- 行动卡采用图标、短动词、实际成本及收益；保持少量选项，不增加逐页确认。
- 下一幕展示上次行动结果。关系形成可由人物递工具、借车等表现，并辅以一句来源说明。
- 结算突出留下的实物、资金和具体关系；次代第一次用到时指出来源，例如“祖辈留下的工具”。
- 不以扩大剧情段落代替剧情设计，不把内部旗标、任务状态名暴露给玩家。

沿用现有分层，不让 UI 自己计算规则或修改存档。节点字段可采用 currentNodeId、nextNodeId 等简单方案，具体命名由实现决定。内容校验只覆盖节点引用有效、可结束和不可卡死等直接风险。

保留用户存档及旧记录入口。已有进行中的六事件任务必须能恢复：提供兼容路径或确定性映射，不删除进度、不重置家庭。新增字段缺失时提供安全默认值。跨代事实兑现和结算保持幂等。

Cocos 当前构建曾出现 Set 展开转译问题；集合转数组使用 Array.from(new Set(...))，避免依赖 [...new Set(...)] 的发布表现。

## 10. 开发顺序与必要验收

1. 先打通经营任务两条路线，包括不同后续、结算和存档恢复。
2. 完成安居任务与四类资产的具体用途。
3. 接入两组关系的跨代后续，再调整任务选择和重复抑制。
4. 同步完善必要的图形场景，进行短时实际试玩。

验收关注：

- 同一经营目标的两条路线在中段和结局确有差异。
- 一次关键选择在随后一至两次行动内产生可见后果。
- 四类家族积累都有改变解法的用途，至少试玩一次上一代成果帮助下一代。
- 随机机会和选择可以改变发展方向，已有工具不强制后代继续木工。
- 机会耗尽、资金不足、部分失败均能走到有效结算，下一代可以开始。
- 在分支中退出恢复不重抽、不丢路线、不重复奖励，旧存档有兼容路径。
- 不打开长篇详情也能知道目标、选择代价和行动结果，点击次数不因反馈页增加。

只运行类型检查、针对分支/恢复/结算的少量必要验证，以及短时 Web 试玩。已有测试保留按需使用；不默认跑千局模拟、全面回归、微信构建或双端发布，不为文案和可逆布局新增镜像测试。

## 11. 后续剧情储备（不属于本轮必做）

- 学艺谋生：学徒、账房、运输等机会，发展方向由事件和选择形成。
- 地方互助：修桥、恢复集市、借场复工，公共环境影响家族生计。
- 家业转向：老生意衰落后改良工艺、改做维修或转向交易，已有积累可转换用途。
- 家庭内部选择：照料长辈、后辈求学与经营安排围绕同一目标形成取舍，避免新增互不相干的支线清单。

先把一个地方、两组关系和两条有分支的主线做得可玩，再按相同标准扩充内容。
