# 家庭与代际成长重构计划

日期：2026-09-09。状态：**已实施**（第一批至第三批内容与第四批最小交付验证均完成）；本文作为后续扩充的依据。现有 v3 轮回玩法继续保留，新家庭玩法使用独立 v4 存档键。

## 1. 产品定位与边界

玩家持续经营一个家庭，每局控制其中一代成员，解决一件影响家庭生活的大事。每代留下的资产、教育条件、家学和声誉，为下一代增加选择。

核心循环：查看家庭成果 → 安排一项家庭建设 → 开始下一代 → 围绕一个任务作出关键选择 → 自动结算贡献 → 回到家园。

长期追求是让家庭从勉强维持生活，逐渐走向生活稳定、有余力学习、能够经营自己的事业。成长的主要设计投入放在跨代系统；家园操作保持简短，不以增加菜单和点击次数来体现深度。

题材采用架空但遵循现实生活逻辑的河畔城镇。首版覆盖三代、约六十至八十年的家庭故事。人物年龄与身份随时间更新，不让同一位师傅跨越数代重复出现；暂不模拟完整历史和时代技术树。

一局代表这一代最重要的一段经历，不必从出生演到死亡。主线结束后，用简短尾声交代之后的生活与交接。后继者可以是已建立关系的成年子女、晚辈或收养的家庭成员，首版自动安排一位，不增加婚育和继承人筛选玩法。

## 2. 首版希望玩家实际感受到的变化

1. 首代结束，家园出现一项有来源的实物或条件改善。
2. 次代前两个事件，就能用上前代留下的条件：打开一个新选项、减少一次成本，或者避开已解决的生活困难。
3. 第三代面对更有发展空间的任务，同时还有与当前家庭条件相适应的选择和风险。
4. 玩家能说清“这一代要做什么”“上一代帮了什么”“这次结束能留下什么”。

目标体验：每代约三至五分钟；首轮三代约十至二十分钟。时间是阅读体验目标，不设置倒计时和强制等待。

## 3. 跨代成长规则

首版只保留一种可分配资源：家庭资金。资产、家学、声誉是具有具体用途的状态或解锁，不再分别制作可刷取的点数条。

| 积累 | 现实载体 | 下一代获得的作用 | 传承限制 |
| --- | --- | --- | --- |
| 生活保障 | 稳定住所、储备、偿清的旧债 | 部分基础开销降低，失败后仍有继续生活的条件 | 已解决的旧债不重复刷新；储备可以被明确事件消耗 |
| 生产资产 | 工具、工作间、店铺 | 出现可执行的新行动、接受订单的资格、较低的操作成本 | 工具不能直接赋予熟练度；房屋改善不等于直接获得商业资产 |
| 教育与家学 | 入学条件、书籍、整理的手册、实际传授 | 学习入口、更快入门、可尝试的基础方法 | 个人熟练度与全部专长不原样继承 |
| 声誉与联系 | 可靠交付记录、与商行或学堂的往来 | 引荐、合作资格、部分信任门槛 | 私人关系随人和年代变化；组织关系需要有交接依据 |

玩家始终控制同一条家庭主线。新一代出生条件受真实家底约束，不会拥有店铺后又被随机重置成一无所有。

每项长期积累都记录来源，例如“第一代：修好旧工作台”“第二代：留下记账手册”。来源默认显示一行，需要时再看详情。

### 家庭建设如何操作

- 家园最多同时展示三个符合条件的建设选项，每个只显示名称、成本和下一代的具体收益。
- 每代之间最多完成一项建设，也可以保留资金直接出发；已有成果自动继承，不需要配装或领取。
- 建设包括修缮、购置、教育安排等；关键资质还需满足本代实际经历，不能单纯用钱买出从未接触的知识。
- 首次成功的结算应足以支持至少一项基础改善，防止开局反复攒钱才见到变化。
- 各类首版仅两级，先实现少量有效解锁；条件不足的远期内容只露出下一项，不铺开整张树。
- 活跃任务中，家庭建设暂停，避免家园消费和局内消费形成两套可同时修改的账本。

资金在局内以“本代可用预算”呈现。开局从家庭资金拨出预算；结算只返还剩余预算与实际净收入。已经支付的成本不重复扣除，任务总收入不再作为额外奖励发放第二次。不可动用的住房等固定资产单独记录，不折算成可花资金。

## 4. 每代一个任务

开局直接给出一项与家庭状况匹配的主线。玩家选择解决方法。目标、期限和主要完成条件开局可见；中途机会可以改变途径，首版不突然替换目标。

每局六至八个关键事件，每个通常两至三个选项。阶段为：交代处境 → 尝试与准备 → 遇见机会 → 运用所学 → 应对关键困难 → 结算。不同任务可增加一至两个分支事件。

每个事件至少承担一个作用：推进任务、提供相关能力、付出代价换取机会、兑现此前积累。删除纯粹凑年龄和展示生活琐事的强制节点。

完成目标后进入尾声结算，不再强制补足一生。失败或期限用尽也进入结算，不要求重复挑战同一个人的相同人生。

### 第一批任务模板

| 任务 | 可见目标 | 不同解决方法 | 可以留下的成果 |
| --- | --- | --- | --- |
| 稳住生活 | 在期限前补足约定开支 | 临工、修理、商量付款安排 | 储备、实用工具、可靠交付记录 |
| 取得独立做工资格 | 完成学习与一件合格作品 | 师傅指导、家学辅助、合作练习 | 手艺基础、作品记录、整理的手册 |
| 让小铺稳定接单 | 完成试营阶段的交付与收支要求 | 改善制作、维护客户、安排订单 | 店铺条件、商行往来、经营方法 |

每个任务只显示一个主要进度。具体条件不同，不把所有任务统一成攒钱：学习任务显示资格阶段，经营任务显示试营阶段，收支要求在相关事件中说明。

任务池由家庭状态筛选。例如已解决住房问题的家庭不再反复收到相同安居任务，拥有生产条件后出现经营任务。发展更好带来新机会，基础任务里已有的优势仍然有效，不以全局同步涨价抵消成长。

## 5. 局内成长与随机性

保留现有动手、沟通、筹划三种个人能力。每代重新形成个人熟练度，家学可以提供合理的基础或更容易入门的条件。

一局主要获得一至两次与主线相关的能力提升；提升后的一至两个事件内安排使用机会。把学习和形成方法融进行动选项，取消固定次数弹出的回望选择页。

选项需要有实际取舍：稳妥但收入少、花预算学习后面回报更大、借助家庭工具节约成本、向人求助但留下合理责任。首版后果以清晰条件为主，不给每次点击叠加隐藏成功率。

随机内容包括机会顺序、可遇见的合作对象、任务中的困难和个人兴趣。随机不改写已经作出的选择，不凭空删除长期成果。关键难题始终有可执行的基础路径；缺少某项传承会影响方法与代价，而不是直接把整局锁死。

同一家学可以跨职业使用。例如记账可以帮助管理工具、安排学费或经营商铺。家庭背景不预先绑定下一代的职业。

## 6. 结算、失败和长期节奏

结算分为达成、部分达成、未达成，直接说明目标结果与净变化。失败保留实际剩余的预算、确实获得的物品和已经形成的知识；不凭空赠送万能经验，也不要求每次失败都获得完整升级。

阶段性损失限于提前说明的预算、任务收益或相关状态。首版不加入全家破产、突然清空家产和家族断绝；已有基础资产不会因一个普通失败整体消失。

长期节奏采用三个可见里程碑：安稳度日 → 有条件培养后辈 → 拥有可持续的家业。达到里程碑解锁新的任务内容与建设，而不仅增加收益百分比。

首版第三代提供家庭阶段总结：展示三代贡献、家园变化和下一步发展方向。它构成一个完整可玩的章节；后续章节另行扩充，不通过反复膨胀数值延长首版。

## 7. 三代示例

第一代为补足家庭开支去做临工，期间选择学习修补。最终完成任务，留下结余和实际得到的一套工具。回到家园，可选择用结余修好工作间，也可留作次代预算。

第二代接到学成独立做工的目标。开局能使用家里的工具，省下租借费用，前代帮助在前两个事件内出现。中途遇到商行机会，可以通过实际订单完成作品要求，并留下交付记录。

第三代具备工作间和可靠交付记录，主线升级为让小铺稳定接单。此人可能偏向沟通与安排，通过合作经营完成目标；不会因为祖辈做木工就必须终身做木工。

如果第一代未完成目标，第二代仍从实际留下的家庭状态出发。任务池给出能继续改善生活的基础任务，不伪造已经获得的工具和经营资格。

## 8. UI 与操作

只保留家园、当代事件、代际结算三个主页面。家史与角色详情作为可选侧页。

| 页面 | 第一视觉重点 | 次要信息 | 主操作 |
| --- | --- | --- | --- |
| 家园 | 当前家庭生活状态与最重要的改善 | 家庭资金、最多三个建设选项、上一代一句贡献 | 建设可选，开始下一代 |
| 当代事件 | 当前发生的事与行动选项 | 顶部一行本代目标、上一行动反馈 | 点选即推进 |
| 代际结算 | 这一代完成了什么、给家庭留下什么 | 净资金变化、下一代可获得的具体帮助 | 回到家园 |

事件页保留已经实现的直接推进与顶部结果反馈，只新增一条紧凑主线目标。能力数值、家庭明细和完整记录放到侧页；选项只显示判断所需的成本、门槛或收益。

成长反馈优先写具体作用，如“用了家里的工具，省下租借费”，并用小标签标出来源；避免只有“传承 +1”。

家园用一幅可随建设改变的简洁场景展示屋舍、工具和工作间，采用现有绘制能力实现初版。低饱和暖底色、深色文字、一种强调色；统一标题和卡片层级，不堆装饰插画、顶部徽章与多排资源条。

沿用点选提交、重复点击保护和自动保存。每代六至八次剧情选择，局间通常为一次返回、零至一次建设、一次出发。没有逐项领奖、确认行动、继续结果和强制阅读档案。

## 9. 对现有系统的处理

| 当前实现 | 重构处理 |
| --- | --- |
| Cocos Creator 3.8.8、运行时 UI、Web 预览 | 保留 |
| `GameApp.ts` 调度、`GameService` 操作边界、presenter 与 UI 分层 | 保留结构，接入新的家庭流程 |
| `chooseAndAdvance`、最近反馈、重复提交保护 | 复用模式，让新任务操作依旧一次提交并保存 |
| 规则 8 的动手、沟通、筹划与条件选项 | 复用概念及合适的纯计算逻辑 |
| 小城、河港、街市和现有剧情 | 按任务需要改写少量素材，重新绑定人物年代和家庭来源 |
| 固定 12 事件、从少年走到 81 岁 | 新玩法改为任务驱动的六至八事件 |
| 固定回望、理解携带、轮回者档案 | 新玩法移出主流程，历史存档需要的旧逻辑保留 |
| 因果来源和经历记录 | 新玩法用于贡献、家学与资产来源；不让旧理解数值自动变成家庭成果 |

不把新家庭状态全部塞进旧 `ReincarnatorProfile`，避免继续混用个人经历和跨代经济。

## 10. 数据与模块方案

建议独立定义以下新模型，具体文件拆分以可读性为准，不搭建通用剧情编辑器或复杂插件框架。

- `FamilyState`：家庭 ID、代数、年代、资金、资产、家学、声誉状态、里程碑、贡献记录。
- `GenerationRun`：本代成员与亲属关系、开局家庭条件快照、个人能力、本代预算、任务状态、随机数状态、待选事件、已处理操作与最近反馈。
- `MissionDefinition`：适用家庭条件、主目标、阶段与事件分支、完成条件、部分完成条件、成果规则。
- `GenerationSettlement`：本代 ID、完成等级、预算返还与净收入、资产与知识变化、贡献来源。
- `FamilySave`：版本、家庭、当前任务、最近结算、已结算代次 ID。

建议模块职责：

| 模块 | 职责 |
| --- | --- |
| `core/familyModel.ts` | 家庭、任务、交接与存档类型 |
| `core/familyEngine.ts` | 家庭建设、继承条件、跨代结算与里程碑 |
| `core/missionEngine.ts` | 任务筛选、阶段推进、条件判断、个人成长 |
| `content/familyContent.ts` | 建设及其条件与具体效果 |
| `content/missionContent.ts` | 第一批任务和事件定义 |
| `app/gameService.ts` | 新旧玩法路由、完整操作与保存边界 |
| `app/presentation/`、`ui/` | 家园、当代事件、结算与可选详情 |
| `platform/` 与存档解析 | 新格式读写及旧存档保留 |

核心数据流：点选 → 校验待选事件 ID 与条件 → 一次生成行动结果、预算与能力变化 → 进入下一节点或生成结算 → 同次更新家庭及已结算标记 → 保存 → presenter 输出界面。

局末家庭增长与结算 ID 一起保存，刷新或重复点击不能重复发放。任务、建设都采用稳定实例 ID。随机状态和当前选项保存下来，刷新不重抽机会。家园在任务进行时只提供查看与续玩，不能直接开启第二代并行任务。

## 11. 存档兼容

建议新玩法使用独立 v4 家庭存档键与明确玩法类型，保留现有 v3 存档和旧引擎。

- 有旧局时可继续原规则，或从家园入口开始新家庭；新家庭默认成为后续主入口，旧入口放在记录页。
- 旧局的经历按原样保留，不推断它们属于同一家族，也不未经依据兑换为家产。
- 加载新存档时不把旧键当成过期数据清除；修正当前存储层的清理入口，明确可清理键范围。
- 格式错误时保留原数据并显示恢复提示，不静默覆盖。

## 12. 实施顺序与交付标准

### 第一批：打通两代的最小闭环

完成家庭模型、新存档、一个任务模板、两项可建设成果、自动交接和最简家园。先在第二代实际展示前代资产开启的选项。

交付标准：能连续玩两代；一个长期成果有可见来源；次代前两个事件兑现帮助；刷新不丢局、不重复结算。优先交付这个可试玩版本，再扩大内容。

### 第二批：形成家庭经营选择

接入生活保障、生产资产、教育家学与声誉；各类最多两级，任务主线扩到三种。完成部分达成与失败的结算，以及基于家庭条件的任务筛选。

交付标准：不同建设至少改变一项实际选项或成本；失败仍可继续；家庭发展后目标合理变化；不出现一项升级对所有局都无条件最优。

### 第三批：完整三代体验与界面收束

补足三代关系与年代交接、家园场景变化、贡献记录、第三代章节总结。首版约十八至二十四个必要事件节点，优先改编已有素材。

交付标准：手机尺寸下目标、事件、选项层级清楚；一屏优先容纳必要操作，较长内容有自然滚动；每局一条主线；实际体验能感到家庭逐代改善。

### 第四批：最小交付验证

运行类型检查和一个针对新闭环的轻量冒烟流程，再构建一次 Web，实际试玩前两代的关键段落。只对发现的问题做针对性复查。

冒烟范围限于：继承成果生效、失败可交接、预算不重复计入、结算只执行一次、待选状态能恢复。旧存档改动补一个代表性载入检查。不运行千局模拟、全量回归或默认微信构建。

## 13. 首版明确不做

复杂族谱、婚育配对、遗产争夺、多人经营、在线排行榜、离线收益、体力与每日任务、房屋自由摆放、地图探索、随机装备词条、大型时代系统、全面剧情扩写。

不为首版安排大规模美术生产或完整旧代码清理。新玩法稳定后，再按实际需要移除旧系统。

## 14. 完成判断

完成重构的依据是可玩的三代闭环：玩家能在家园作出有影响的建设选择，在一条明确主线中使用家庭积累，并在结算中看到下一代获得了哪些真实条件。架构整理和文案替换服务于这一体验，不单独视为玩法完成。
